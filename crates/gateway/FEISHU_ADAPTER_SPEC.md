# Feishu/Lark stock plugin implementation spec

Register one bundled Rust adapter as `feishu` for Feishu and Lark. Start after Google Chat passes live acceptance and the expanded shared contract passes conformance. An installed bot can serve authorized chats and threads, respond to native cards and share rich posts and files. Optional provider document and meeting events use normal native authority with their own grants. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [Google Chat spec](GOOGLE_CHAT_ADAPTER_SPEC.md) · [Hermes Feishu/Lark guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md) · [Next adapter, DingTalk](DINGTALK_ADAPTER_SPEC.md)

## Registration and intake

Put the factory and wire clients in `hermes-gateway::messaging::feishu`. Select Feishu or Lark explicitly and bind its API region, verified app and bot identity, authorized tenant and credential revision to the profile. Verify the tenant access token, bot identity and required scopes. Support manual credentials and the provider's scan-to-create enrollment where the selected region offers it. Keep the QR and polling state owner-private and expiring. Show publication, scopes and event versus card callback subscriptions independently. One active lease serves each app installation. A credential rotation that verifies the same installation preserves bindings. No regional endpoint or token fallback across installations. [Mercury adapter seam](src/messaging/types.rs) · [Hermes setup and scopes](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#step-1-create-a-feishu--lark-app)

- **Long connection.** Use authenticated vendor connection discovery and its framed WebSocket protocol. Bound frame and multipart reassembly by connection, expiry and size. Handle heartbeats and rebuild exhausted links with bounded backoff. Use the provider response timing for events and callbacks. Commit the disposition or durable handoff before sending a success acknowledgement. A card callback needs its durable native decision before returning a successful decision response. Fence late frames and callbacks after replacement. [Provider long connection client](https://github.com/larksuite/oapi-sdk-python/tree/v1.4.24/lark_oapi/ws) · [Hermes Feishu transport modes](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#step-2-choose-a-connection-mode)
- **HTTPS webhook.** Bind the challenge, verification token, encryption material and callbacks to the designated receiver and app. Check the provider signature over the original bytes using the configured encryption key, timestamp and nonce, and validate freshness before decrypting event bodies. Require the configured verification token and app/tenant match before handing off a message. Answer the setup challenge under its specific provider token rules. Enforce bounded body size and request time, and keep quota isolation for authenticated traffic. Return successful event receipts only for committed dispositions. [Feishu receiving callbacks](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks) · [Hermes webhook verification](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/feishu/adapter.py#L2678)

Normalize `im.message.receive_v1` by app, tenant and provider message ID. Preserve authenticated event IDs for delivery deduplication and use resource and action identities for logical work across transports. Route membership changes, reads, reactions and own bot echoes as typed state or receipt evidence. An authenticated app sender still needs a peer bot grant, mention policy and loop protection before it can initiate a turn. Persist intake and short text or media bursts by exact sender, room and reply route, with bounded count, bytes and timeout. Commands and interactive callbacks take their normal authority path. Reconnect uses provider retries and durable staged input. There is no assumed WebSocket history cursor. Expose any unproven interval as a gap. [Hermes Feishu batching and dedup](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#burst-protection-and-batching)

## Chats, interactive cards and provider events

**Routing.** Bind DMs and group chat IDs under the verified tenant and app. Treat app-scoped `open_id` and other authenticated identifiers as scoped aliases only after proving equivalence. Apply room rule precedence, including owner-controlled admins, allowlist, blacklist and disabled groups, then exact bot mentions and explicitly enabled free response. Keep shared-group conversation history per actor by default and allow explicit shared mode. Resolve root, parent, topic and quote relations under the originating chat's authorization. Capture a reply resource and thread semantics at admission. Apply the configured turn-local group prompt at claim. Membership loss blocks protected reads or sends. [Hermes group access](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#per-group-access-control)

**Cards and controls.** Support typed commands, model and settings pickers, update confirmation, clarification and approval cards. Register `card.action.trigger` as a callback separately from message events. Bind provider actor, context, original card, opaque action ID and generation to the pending native request. Scope callbacks custom-authored by allowed skills to their declared command and argument schema. A raw card value cannot mint an operator command, choose a profile or supply an approval decision for a different prompt. Record the action before responding. Return the provider's supported card update or toast within the callback deadline, or recover its presentation through a separately recorded effect. Repeat decisions use their persisted outcome. Text interaction remains available where the published app lacks card callbacks. [Feishu card interactions](https://open.feishu.cn/document/feishu-cards/configuring-card-interactions) · [Hermes Feishu card workflows](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#interactive-card-actions)

**Document comments.** Enable `drive.notice.comment_add_v1` only with configured document rules, explicit eligible authors or pairing and the required Drive and Docs scopes. Apply exact resource, matching pattern, then workspace default rules. Prove the mention targets this bot. Dedup by verified document, comment thread and originating reply/event ID. Load bounded authorized document and comment context, support whole-document and selection threads, and keep the scoped turn and any granted document tools bound to that resource. Retain durable reply intent to the exact comment thread. Recheck grants before reading or publishing. Use private rule and pairing operations. A chat allowlist alone grants no document access. [Hermes document comment behavior](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#document-comment-intelligent-reply)

**Meeting invitations.** Gate `vc.bot.meeting_invited_v1` by feature, app scope, authorized inviter, exact meeting number and a configured meeting capability. Stage one structured invitation for native authority. A missing join capability or denied meeting produces an authorized notice to the verified inviter where permitted. Record the exact handoff and outcome so redelivery cannot repeat a committed join. Meeting media, transcription and conferencing internals depend on the separate runtime capability. [Hermes meeting invitation routing](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#meeting-invitation-events)

## Media and delivery

Stage authorized images, voice, videos, files and rich post attachment references through the selected region and tenant. Keep captions and attachment-only input. Extract bounded supported text attachments and transcribe through shared services. Render text or rich Markdown posts, including localized rich contents, and bound chunks by provider limits. Use plain text after a definite rich payload rejection. Track the confirmed reaction ID for the optional working marker. Retire or replace only the bot's reaction at completion. Upload images and files to obtain scoped keys, then publish file, audio, image or media in order. Qualify native voice playback with the accepted codec and client. Keep upload and message receipts separate. [Hermes Feishu media and status](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/feishu.md#media-support)

Prepare each create/reply with a stable `uuid` and exact immutable payload, author, destination, root and reply mode. Persist message IDs and intermediate file keys. Retransmit only within the verified API's deduplication scope and time window. Outside that guarantee use exact evidence or an operator resolution. Keep reply context when an existing thread cannot be posted to. Permit a parent audience only with explicit final-notification policy and definite rejection. Bind proactive and manual sends to an authorized home chat or thread under the same lease and outbox. [Lark message creation](https://open.larksuite.com/document/server-docs/im-v1/message/create) · [Lark reply API](https://open.larksuite.com/document/server-docs/im-v1/message/reply) · [Hermes send implementation](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/feishu/adapter.py#L3789)
