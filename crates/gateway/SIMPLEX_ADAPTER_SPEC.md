# SimpleX Chat stock plugin implementation spec

Register SimpleX Chat as a bundled Rust adapter with platform key `simplex`. Start after LINE and the shared gate. A headless profile uses an operator-managed SimpleX daemon to serve approved contacts and groups, exchange native XFTP attachments, and send queued or scheduled results within the same protected chat. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [LINE spec](LINE_ADAPTER_SPEC.md) · [Hermes SimpleX guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/simplex.md) · [Next adapter, IRC](IRC_ADAPTER_SPEC.md)

## Daemon ownership and intake

Put the factory, typed command encoder and WebSocket client in `hermes-gateway::messaging::simplex`. The supported daemon keeps its encrypted chat store and communications keys. A dedicated private loopback endpoint in the daemon's isolated environment is the default. An explicitly authenticated private deployment requires equivalent access controls and a scoped file exchange. A plain public WebSocket is refused. Establish the daemon store binding and active local user through the qualified API. Scope numeric IDs by that binding. Fence stale generations on disconnect, active-user change or daemon replacement. Use typed command construction for structured `/_send` and other daemon calls. Correlation IDs match responses under one connection. Parser inputs, rendered parts and media path strings cannot inject additional commands. [Mercury adapter boundary](src/messaging/types.rs) · [SimpleX CLI](https://github.com/simplex-chat/simplex-chat/blob/stable/docs/CLI.md) · [SimpleX command API](https://github.com/simplex-chat/simplex-chat/blob/stable/bots/api/COMMANDS.md)

Normalize `newChatItems` and file lifecycle events, checking account and received item direction. Use chat/item identities from the verified store. Record ordinary items, state changes and recognized file notices durably. Ignore own sent items as input while retaining exact effect evidence. Treat idempotent contact acceptance and Mercury DM pairing as separate actions. Support operator-approved contact requests and explicitly enabled auto-accept without granting the resulting contact agent access. Keep rapid text bursts under the shared batching rule. Any transient message ID or missing reference that cannot be resolved from the daemon stays unproven. [SimpleX events](https://github.com/simplex-chat/simplex-chat/blob/stable/bots/api/EVENTS.md)

Live WebSocket events have no portable replay cursor. Retain per-chat durable item anchors and use bounded, authorized daemon history through the supported chat query for repair where those anchors survive. Establish a fresh baseline on initial discovery. On reconnect merge live and recovered copies by the original chat item ID, preserving source order per chat. Treat expired, disappeared or inaccessible data as an explicit gap. Do not ingest historical scrollback as a new turn at first binding. Persist a complete scoped transfer handoff before acting on a file offer. [SimpleX scoped chat history API](https://github.com/simplex-chat/simplex-chat/blob/stable/bots/api/COMMANDS.md#apigetchat) · [Shared replay](ADAPTER_CONTRACT.md#intake-ordering-and-execution-recovery)

## Routes, controls and files

Use the daemon's numeric direct `contactId` and group `groupId` plus `memberId`. Apply DM allowlist or owner pairing, group allowlist and verified member policy. Groups default disabled. A name is display-only, except an owner can resolve a unique directory entry to an explicitly verified durable destination. Enumerate authorized contacts and joined groups for home and manual delivery without exposing hidden names or opening turns. Respect protected transport and provider retention features. Decline content retention modes that cannot be honored. Native text commands and controls go through the profile owner. Support item quotes where the qualified structured API can bind the exact source and chat. [Hermes SimpleX routing](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/simplex.md#authorization)

On a verified `rcvFileDescrReady` or a related chat item, bind its transfer ID to the original authorized actor and exact item. Apply current size, media, storage and relay policy before issuing `/freceive`. Stage an authorized receive directory and retain pending disposition until `rcvFileComplete`, valid existing transfer state or a terminal error. A completion without a matching authorized item grants no filesystem read. Read a bounded regular file from the designated exchange and reject path or symlink escapes. Stage into private profile storage, preserve caption and media type, and use native transcription for voice. Handle file-only intake and late completion without a second turn. Outbound native image, voice, video or file uses a scoped file exchange and structured `/_send` under the same route. Preserve any necessary daemon file lifetime until confirmed transfer or owner resolution. [Hermes XFTP flow](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/simplex.md#attachments) · [SimpleX receive command](https://github.com/simplex-chat/simplex-chat/blob/stable/bots/api/COMMANDS.md#receivefile)

## Delivery and recovery

Send supported text or structured composed media and capture the daemon's confirmed sent item identity and exact destination. A successful frame write or `corrId` is insufficient to confirm an external effect. Separate local daemon acceptance from later transport or recipient status. After disconnect query exact persisted item/effect association where qualified. Otherwise wait for operator resolution of ambiguous sends and keep order for that route. Revalidate membership and protection before dispatch and after replacement. An approved home contact or group receives scheduled and manual results through the same outbox. [Hermes command handling](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/simplex/adapter.py#L445)

## Implementation and acceptance

| Step | Prerequisite | Evidence |
| --- | --- | --- |
| Private daemon binding | LINE live acceptance and shared gate | Scope verification, account fencing, bounded stream replay/repair and item dedup. |
| Native sessions and XFTP | Durable input | Authorized direct/group routing, target discovery, media staging and typed controls. |
| Live acceptance | Transport and shared conformance | Real qualified daemon and clients prove recovery, native files and approved proactive delivery. |

Use scripted daemon responses through the production adapter and Mercury owner. Cover identical numeric IDs from two stores, a forged or stale command correlation, replay overlap, late file completion after restart, forbidden transfer before `/freceive`, path escape, DM or group grants removed before delivery, and lost `/_send` response with and without exact evidence. Run shared conformance and `cargo test --locked --workspace`. In a real direct contact and joined group, verify pairing, denied access, text commands, quote-capable reply if enabled, image/voice/file both ways, daemon and gateway restart, and a scheduled result to its verified group or contact. Record daemon version and supported history and media behavior. [Hermes SimpleX fixtures](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_simplex_inbound_files.py)

## Scope

Keep the SimpleX cryptographic transport and daemon database owned by SimpleX. Exclude standalone senders, direct reads of the daemon database, and Desktop UI. [Backend parity scope](../../BACKEND_PARITY_PLAN.md#scope)
