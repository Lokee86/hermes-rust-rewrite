# Raft stock plugin implementation spec

Register Raft as a bundled Rust external-agent adapter with platform key `raft`. Start after ntfy and the shared gate. The authenticated local bridge wakes a named Mercury session. The Raft CLI reads messages and posts replies under the verified External Agent profile. An authenticated wake acknowledgement records gateway acceptance of a trigger. Message delivery has its own CLI and provider evidence. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [ntfy spec](NTFY_ADAPTER_SPEC.md) · [Hermes Raft guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/raft.md) · [Raft external-agent behavior](https://docs.raft.build/developers/sdk/external-agents/wake-and-status/)

## Setup and local bridge

Put the factory, receiver and process supervision in `hermes-gateway::messaging::raft`. Privately enroll the operator's Raft External Agent with the supported CLI. Verify the exact server/workspace, external agent identity and CLI profile before leasing the bound native Mercury session. Reuse its provider profile on restart and fence replacements. Launch the qualified `raft agent bridge` wake-channel mode under the gateway owner, using a private loopback endpoint and a random generation-scoped shared token. Scrub the process environment, limit filesystem/credential access to the approved Raft profile, and use fixed arguments. Gateway shutdown and owner death release the entire child lifecycle. Report receiver readiness, bridge process and upstream reachability separately. Restart failures with bounded backoff. [Mercury adapter seam](src/messaging/types.rs) · [Raft External Agent setup](https://docs.raft.build/developers/sdk/external-agents/) · [Hermes bridge spawn](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/raft/adapter.py#L327)

## Content-free durable wake

Accept only authenticated, bounded JSON on the wake endpoint. Require the profile-bound token and an exact supported wake metadata shape. Keep bounded scalar identifiers and provider times as transport evidence. If the qualified bridge includes a reply-target hint, treat it as opaque metadata and discard it from native authorization and model context. Refuse any embedded message body, preview, arbitrary instructions or unknown content-shaped fields. Use a stable upstream wake identity under the verified External Agent and transport scope. A changing delivery attempt ID can corroborate a retry but cannot rename the logical wake. Require evidence of stable identity for retryable wake delivery. [Hermes wake handler](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/raft/adapter.py#L449)

Translate a wake to a typed internal trigger with fixed context supplied by the profile. Bind it to the configured native session and current permission generation. Return HTTP 202 only after durable acceptance, staged work or recognized repeat. A not-ready or uncommitted wake uses a retryable response. Coalesce compatible committed hints while one native run is busy. Store which sequence of pending wakes that execution covers. A later wake remains pending until an authorized follow-up observes it, including after restart. Preserve gateway idle, busy and uncertain claim semantics. A wake never steers, interrupts or acts as an approval. [Shared intake and execution](ADAPTER_CONTRACT.md#intake-ordering-and-execution-recovery)

## CLI messages, replies and activity

Use the qualified profile-bound Raft CLI to check/read messages and send replies, surfaced through scoped native tools. Keep per-inbox message identities, verified reply target and inbox acknowledgement evidence in authorized tool results and recovery state. Raft's CLI handles read cursor protocol. Preserve the tool observation needed before a subsequent CLI check confirms a previous batch. Repeat inbox items do not repeat a committed reply. If an interrupted send lacks exact provider evidence, leave the native tool effect uncertain for reconciliation and preserve the original Raft target. Expose command failure, held or confirmed provider sends as their actual outcomes. The wake adapter advertises no text emission, and should return typed unsupported for direct native delivery rather than synthetic success. Agent actions and provider credentials stay inside the selected profile and external identity. [Raft wake and inbox acknowledgement](https://docs.raft.build/developers/sdk/external-agents/wake-and-status/) · [Hermes Raft adapter boundary](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/raft/adapter.py#L413)

Support the qualified bridge's authenticated local activity publish and drain protocol. Use bounded, schema-checked records with stable event ID, session identifier and native lifecycle status or authorized tool metadata. Enable only for this Raft-bound context. Redact content and secrets by default. Detailed tool activity requires explicit policy for its destination. Expose bounded queue loss according to the bridge protocol. Activity visibility and drain acknowledgement are separate from wake admission and message delivery. A stalled activity reader cannot block wake receipts or native work. [Hermes Raft activity queue](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/raft/adapter.py#L182) · [Raft reported status](https://docs.raft.build/developers/sdk/external-agents/wake-and-status/)

## Implementation and acceptance

| Step | Prerequisite | Evidence |
| --- | --- | --- |
| Bridge lease and setup | ntfy live acceptance and shared gate | Verified CLI identity, scoped worker lifetime and authenticated private receiver. |
| Durable wakes and CLI boundary | Verified bridge | Content-free intake, busy/restart recovery, CLI message and send evidence, scoped activity drain. |
| Live acceptance | Transport and shared conformance | Real External Agent receives a wake, reads and responds through CLI and reports scoped activity after restart. |

Use an executable bridge fixture and scripted CLI through the production adapter and profile owner. Verify missing/stale token, wrong profile and external agent, payload size and content rejection, repeated hint after lost 202, fresh hint during busy execution, restart before and after commit, CLI receipt loss, exact reply routing, unsupported native send and capped activity drain. Run shared conformance and `cargo test --locked --workspace`. With a real Raft workspace verify external-agent enrollment, a UI or CLI message waking the proper session, CLI read and reply, duplicate/restart behavior, and activity isolation across two distinct profiles. Record CLI version, upstream warm reconnect behavior and proof of the actual reply. [Hermes Raft fixtures](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_raft_adapter.py)

## Scope

Exclude legacy Hermes prompt/environment compatibility, Raft server administration, a public inbound message API, generic text send through the wake channel, and Desktop UI. [Backend parity scope](../../BACKEND_PARITY_PLAN.md#scope)
