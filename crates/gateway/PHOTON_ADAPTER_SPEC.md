# Photon iMessage stock plugin implementation spec

Register managed Photon iMessage as a bundled Rust adapter with platform key `photon`. Start after BlueBubbles and the shared gate. A headless Mercury profile enrolls a managed line, serves authorized private and group iMessage spaces, and sends supported text, effects, polls and files through Spectrum. This integration is independent of the operator-managed Mac bridge. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [BlueBubbles spec](BLUEBUBBLES_ADAPTER_SPEC.md) · [Hermes Photon guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/photon.md) · [Next adapter, Email](EMAIL_ADAPTER_SPEC.md)

## Enrollment and Spectrum boundary

Put registration, session normalization and sidecar supervision in `hermes-gateway::messaging::photon`. Qualify the provider-supported Spectrum SDK's long-lived gRPC receive/send adapter. Implement the current SDK integration behind one narrow, supervised Node sidecar. Use a pinned runtime and SDK, a private loopback credential or equivalent isolated IPC, bounded messages and generation-fenced lifetimes. Spawn and repair the bridge through the Mercury owner. Keep supervision, stream health and upstream catch-up status independent. The bridge should own only SDK session and wire operations. Mercury owns user policy, native controls, durable admissions, media grants, outbox and confirmations. Keep a separate public API out of the bridge boundary. [Mercury adapter types](src/messaging/types.rs) · [Spectrum SDK](https://github.com/photon-hq/spectrum-ts) · [Hermes Spectrum sidecar](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/photon/sidecar/README.md)

Use the official device-code flow through an expiring private setup session. Verify the dashboard account, Spectrum project and assigned iMessage line and the intended registered phone. Create or select the intended project and user under a lease with exact recoverable provisioning evidence. Separate management token and runtime project secret. Re-running setup reopens the same confirmed binding; rotate its secret only as an authorized change. Scope each sidecar generation to that specific project, line and profile, with secret redaction and no ambient project inheritance. Show native reachability and required provider provisioning before marking ready. [Hermes setup flow](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/photon/cli.py)

## Durable stream and authorized routes

Normalize verified project, line, space, sender and original message or control identity from SDK events. Use typed DM/group space IDs, a verified phone or handle alias and exact thread/quote metadata when supplied. Never infer a group is a DM from a missing type or overwrite a space with another alias. Preserve exact identity on repeated deliveries, including restart. Handle the SDK handoff with backpressure and durable staging of data that cannot be re-fetched after iteration. Local NDJSON or IPC success is not a durable owner acknowledgement. Preserve any SDK cursor/sequence across recoverable handoff. Use provider catch-up only under a qualified position and prove each repaired interval. Otherwise report unfilled gaps and retain locally staged work. [Hermes stream normalization and catch-up](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/photon/sidecar/index.mjs#L642)

Apply verified phone or peer grants, DM pairing and group/sender policy before native claim or protected reads. Support authorized text and opt-in spoken addressing. Stage only necessary voice for the latter. Mark read or emit typing only under eligible disposition and the owner's notification policy. Provider read and delivery signals update telemetry or exact receipts without admitting work. For attachment placeholders, previews and mixed content, stage relation evidence with a bounded wait and admit one eligible input when complete. Correlate only by exact provider evidence; never discard a separate photo simply because it followed a URL. [Hermes Photon event handling](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/photon/adapter.py#L885)

## Controls and media

Route commands and scoped approvals to native authority. Offer native poll clarification when the event includes a verifiable choice and original posted poll identity. Bind actor, space, action, expiry and native generation. Lost or duplicate votes read one decision. A vote with insufficient association uses an authorized text clarification path. Use Tapbacks on supported exact message identities, including qualified incoming reactions to the gateway's own output. Keep reactions distinct from approvals and ignore provider receipts as commands. Provide native typing, read receipts, rich links and opted-in iMessage effects under advertised capabilities. [Hermes poll and reaction handling](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/photon/adapter.py#L918) · [Spectrum iMessage features](https://github.com/photon-hq/spectrum-ts/tree/main/packages/imessage)

Capture media attachments only after applicable authorization, with bounded bytes and transfer lifetimes. The Hermes v0.23.4 guide says inbound attachments are metadata-only, but its pinned sidecar reads and forwards bounded bytes through the SDK. Cover that implemented behavior for images, video, documents and voice. Fall back to verified metadata when the SDK cannot obtain or bound content. Use the shared transcription service for eligible voice. Outbound media, native voice and caption publication are distinct ordered effects so an accepted upload or visible attachment need not repeat after a caption failure. Expose only scoped per-effect artifact references to the sidecar. [Hermes binary normalization](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/photon/sidecar/index.mjs#L433)

## Delivery and recovery

Submit typed send operations through the verified project, line and space, storing exact request scope and provider message ID. Preserve acceptance, provider delivery updates and any uncertain effect separately. After sidecar failure, exact authenticated provider history or the applicable retry guarantee can settle an in-flight send. A local request ID alone cannot. Retry only supported effects for the same identity and audience. Shared-line initiation and quotas are provider-controlled. Verify eligibility at dispatch and after restart. Provision home notifications for an eligible existing space, or a qualified dedicated-line route with explicitly verified new-conversation authority. Use known scope for outbound effects and keep blocked results visible. [Hermes Photon delivery limits](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/photon.md#limits-today) · [Photon shared line routing](https://photon.codes/blog/how-we-rebuilt-our-shared-imessage-routing-to-handle-10m-messages-a-day)

## Implementation and acceptance

| Step | Prerequisite | Evidence |
| --- | --- | --- |
| Project, line and sidecar | BlueBubbles live acceptance and shared gate | Private setup recovery, authenticated bridge control and per-profile process isolation. |
| Native intake and effects | Durable SDK handoff | Exact DM/group routes, identifier and attachment correlation, scoped poll and Tapback, verified outbox. |
| Live acceptance | Transport and shared conformance | Real Spectrum project and iMessage clients verify controls, media, allowed delivery and restart. |

Use the production Mercury adapter through a scripted SDK bridge and real owner. Verify rotation, stale sidecar, project/line isolation, SDK catch-up failure, local handoff loss and replay, short-lived content, forbidden audio and read receipts, false preview association, forged poll votes, partial caption delivery and blocked new-recipient send. Run shared conformance and `cargo test --locked --workspace`. In a qualified deployment verify DM pairing, an allowed and denied group actor, attachment and voice both ways, native poll/Tapback/read where supported, sidecar and gateway restart, and an authorized home delivery. Record SDK and service versions, line plan, known catch-up scope and native capability results.
