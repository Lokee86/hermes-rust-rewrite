# IRC stock plugin implementation spec

Register IRC as a bundled Rust adapter with platform key `irc`. Start after SimpleX and the shared gate. A headless profile can connect to a configured IRC network, work in authorized DMs and addressed joined channels, and send bounded plain-text replies and scheduled results. Qualify enhanced identity, confirmation and replay only when the network negotiates them. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [SimpleX spec](SIMPLEX_ADAPTER_SPEC.md) · [Hermes IRC guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/irc.md) · [Next adapter, Buzz](BUZZ_ADAPTER_SPEC.md)

## Connection and routing

Put the factory and IRC line client in `hermes-gateway::messaging::irc`. The adapter owns TLS, IRC registration and capability decoding, line framing and status evidence. The owner stores the private credential references, verified network/account binding, policy and durable work. Use TLS with hostname validation and optional owner-selected private trust for a self-hosted network. Permit explicitly trusted private plaintext networks only for a compatible policy and no sensitive credentials. Support configured server authentication and SASL where offered, and documented NickServ login on a qualified network that uses it. Acquire one lease per network and registered bot identity, or configured nickname for a plain connection. Resolve a nickname collision with a status change and explicit configured alternative. Do not assume a fallback nick retains account rights. Handle PING/PONG, registration numerics, reconnect backoff, joins, nick and membership changes. Track verified registration and individual channel readiness. [Mercury adapter types](src/messaging/types.rs) · [IRCv3 SASL](https://ircv3.net/specs/extensions/sasl-3.2)

Normalize CASEMAPPING, channel prefixes and negotiated line lengths. Accept `PRIVMSG` to the current bot nick as DM and to an authorized joined channel under exact address or explicitly granted free response. Recognize the provider's negotiated account identity for privileged policy, including account changes and nick turnover. A nick-only grant is explicit and limited to the chosen trusted network and permitted nonprivileged route. It grants no private approval or session control under a reused nickname. Reply to a verified current actor or joined channel and keep ordinary group and per-user binding policy. Normalized CTCP ACTION is display text. Refuse other CTCP/control frames as turn input and suppress own echoes. IRC protocol commands never come from agent text. [IRC account tags](https://ircv3.net/specs/extensions/account-tag) · [Hermes IRC dispatch](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/irc/adapter.py#L275)

## Intake and continuity

Durably stage valid line observations before native claim. Use network-scoped `msgid` with verified room evidence when negotiated. Otherwise a connection-generation and observation ID establishes local handoff identity only. Preserve deliberate repeated messages. Mark discontinuities after disconnect on basic servers. When a supported history extension offers exact IDs and anchors, repair only configured authorized rooms within a budget, merge live and history items by logical identity and disclose gaps. Use baseline semantics on join and avoid turning unsolicited history playback into work. Route text commands, approvals and clarification through native authority under the applicable verified access policy. [IRCv3 message IDs](https://ircv3.net/specs/extensions/message-ids) · [IRCv3 chat history](https://ircv3.net/specs/extensions/chathistory)

## Plain-text delivery

Split text into `PRIVMSG` frames on UTF-8 boundaries, accounting for server wire size, command overhead and target. Use the conservative 450-byte content budget only when it fits the negotiated line ceiling. Sanitize CR, LF, NUL and embedded protocol delimiters. Apply flood limits and server retry deadlines. Recheck membership before dispatch and DM account-to-current-nick mapping after reconnect. Preserve destination and authorization while working offline. With qualified echo or labeled-response evidence, record exact acceptance. Without provider receipt, expose only a complete write as submitted to the connection under an enabled limited-delivery profile policy. An interrupted, partially written or uncommitted attempt remains uncertain and cannot automatically resend. A current allowed home channel receives scheduled, webhook and manual results using the same ordered outbox. [IRCv3 echo-message](https://ircv3.net/specs/extensions/echo-message) · [IRCv3 labeled response](https://ircv3.net/specs/extensions/labeled-response)

## Implementation and acceptance

| Step | Prerequisite | Evidence |
| --- | --- | --- |
| Network and scope | Shared gate and SimpleX live acceptance | Verified TLS, authentication, multi-channel lifecycle and persistent account boundaries. |
| Text intake and outbox | Leased connection | DM and addressed-channel turns, nick changes, bounded frames, uncertainty and limited write evidence. |
| Live acceptance | Transport and shared conformance | Real IRC clients on qualified plain and enhanced network configurations prove their advertised capabilities. |

Use a scripted IRC endpoint and real profile owner. Verify partial frames, registration, membership changes, account/CASEMAPPING, inherited nick refusal, TLS failures, malformed lines, CRLF injection prevention, duplicate message IDs and intentional repeats without IDs. Break the socket before and after a write, verify uncertain sends are held and receipt scope is enforced. Repeat with server echo and bounded history where enabled. Run shared conformance and `cargo test --locked --workspace`. Use a current supported server with real clients for DM and channel mention, scoped text control, multiline output, reconnect, denied nick or actor and home notification. Record negotiated capabilities and confirm any advertised fallback or enhanced claims. [Hermes IRC fixtures](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_irc_adapter.py)

## Scope

The IRC reference is plain text. Exclude DCC and native media, reactions, typing, threaded or editable streaming, old config compatibility, standalone senders and Desktop UI. [Backend parity scope](../../BACKEND_PARITY_PLAN.md#scope)
