# Email stock plugin implementation spec

Register Email as a bundled Rust adapter with platform key `email`. Start after Photon and the shared gate. A dedicated profile mailbox receives authenticated email through IMAP, hands approved mail and attachments to the native session owner, and sends threaded responses or scheduled messages through SMTP. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [Photon spec](PHOTON_ADAPTER_SPEC.md) · [Hermes Email guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/email.md) · [Next adapter, Twilio SMS](SMS_ADAPTER_SPEC.md)

## Registration and transport

Put the adapter factory, IMAP/SMTP clients and bounded MIME handling in `hermes-gateway::messaging::email`. Bind the dedicated authenticated mailbox, selected inbox, sending identity and endpoints to the profile owner. Require verified implicit TLS or STARTTLS as configured, with explicit trust for a local bridge certificate. Use supported provider OAuth for managed services that require it, including Exchange Online, and provider-supported app or dedicated bridge credentials where valid. Separate token purpose, refresh and provider scopes. Pin the receiving MTA's `authserv-id` and verify the receiving trust boundary during setup. Show inbound and outbound readiness independently. Preserve receipts for same-account rotation. Do not let a new mailbox reuse the old route or poll state. [Mercury adapter seam](src/messaging/types.rs) · [Gmail IMAP and SMTP OAuth](https://developers.google.com/workspace/gmail/imap/xoauth2-protocol) · [Exchange Online modern authentication](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/deprecation-of-basic-authentication-exchange-online)

## Durable IMAP intake

Establish a first-connect mailbox baseline, then persist mailbox identity, `UIDVALIDITY`, the safe UID interval and any pending preparations. Poll the selected inbox for new eligible unseen mail. Use UID-addressed fetch and `BODY.PEEK` for headers and bounded bodies so reads do not mark input consumed before durable disposition. Keep uses of sequence numbers session-local. Persist accepted, denied or pending work before advancing the safe frontier or changing the seen flag under mailbox policy. A transient read leaves eligible work recoverable. A UID validity reset or mailbox move requires re-verification and bounded reconciliation with exact provider evidence; report unfilled gaps and prevent numeric UID reuse from shadowing old receipts. Treat RFC Message-ID as correlation and threading metadata. Use verified stronger provider evidence for logical copies across mailboxes or epochs. [IMAP RFC 9051](https://www.rfc-editor.org/rfc/rfc9051.html) · [Hermes header-first fetch](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/email/adapter.py#L691)

## Sender policy, mail threads and MIME

Parse exactly one mailbox in `From` using a bounded header read. Trust the topmost `Authentication-Results` only when it matches the exact configured receiving service and setup established that the MTA strips inbound imitations of that stamp. Require the applicable aligned DMARC, SPF or DKIM evidence before body fetch, pairing or reply. Domain alignment alone confers limited sender assurance. Keep authorization scoped to a complete address and policy. Sensitive approvals require matching native actor authority with sufficient additional proof. Support explicit defaults for unknown senders, opt-in pairing and bounded authenticated declines. Filter loop mail, own submissions, bounces, mailing lists and automated messages. Respect a trusted bridge's specific assertion only when qualified. [Authentication-Results RFC 8601](https://www.rfc-editor.org/rfc/rfc8601.html) · [Hermes Email sender policy](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/email.md#access-control)

Bind the verified sender and original mail thread, with a scoped sender conversation when no related message is known. Accept an `In-Reply-To` or `References` binding only when it matches authorized stored context for that sender and mailbox. Preserve the original subject and related message identities on the admitted turn. Default reply to the verified sender alone. A sender-chosen `Reply-To`, recipient list, or new audience needs a separate explicit authorized binding. Route ordinary text commands and eligible controls through native authority. Parse bounded MIME nesting, part count, encoded and decoded sizes. Prefer plain text, reduce HTML-only input to inert text and avoid external image fetching. Validate type and filenames. Keep file-only inputs where supported and allow owner-configured skipping of attachments before decoding. [Internet Message Format RFC 5322](https://www.rfc-editor.org/rfc/rfc5322.html) · [Hermes Email media behavior](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/email.md#how-it-works)

## SMTP and recovery

Prepare one immutable UTF-8 MIME reply under the original route with bounded subject, `In-Reply-To`, `References`, stable emitted `Message-ID` and attachments. Validate header folding and envelope addresses. Qualify SMTPUTF8 where required. Keep SMTP final DATA acceptance independent of per-recipient envelope rejection and later remote delivery. A definitive temporary refusal can retry under current policy. A lost final acknowledgement after the data terminator is uncertain; the generated Message-ID does not guarantee SMTP deduplication. Use an authorized exact sent observation when the submitted content and destination can be verified. Keep asynchronous bounces or `DSN` outcomes as later scoped status, without creating agent turns. Send to configured verified home addresses from the same outbox after restart. [SMTP RFC 5321](https://www.rfc-editor.org/rfc/rfc5321.html)

## Implementation and acceptance

| Step | Prerequisite | Evidence |
| --- | --- | --- |
| Verified mailbox and IMAP | Photon live acceptance and shared gate | Authenticated TLS, scoped setup, one polling lease, durable UID validity and recovery. |
| Policy, MIME and SMTP | Header-first durable intake | Trusted sender evidence, native threaded reply, checked attachments and classified SMTP outcome. |
| Live acceptance | Transport and shared conformance | Real mailbox, supported auth and mail clients prove dedup, MIME and SMTP after restart. |

Use scripted IMAP and SMTP endpoints through the production adapter and actual owner. Cover UIDVALIDITY change, expunged and reused UIDs, loss before seen update, unseen mail while offline, malformed and forged Authentication-Results, unauthorized body fetch, cross-thread reference, attachments and HTML sanitization, SMTP rejection before and after DATA, and a lost final response. Run shared conformance and `cargo test --locked --workspace`. Use a dedicated real mailbox and clients. Verify authenticated and denied senders, reply threading, file round trip, operator control where authorized, and a scheduled message following restart. Qualify OAuth or supported dedicated credentials and any advertised local bridge mode. [Hermes Email fixtures](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_email.py)

## Scope

Exclude Exchange Basic Auth migration, implicit trust of Internet From headers, legacy Hermes configuration, standalone senders, arbitrary mailbox administration and Desktop UI. [Backend parity scope](../../BACKEND_PARITY_PLAN.md#scope)
