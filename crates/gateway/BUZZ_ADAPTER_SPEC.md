# Buzz stock plugin implementation spec

Register Buzz as a bundled Rust adapter with platform key `buzz`. Start after IRC and the shared gate. A headless profile can work as a community member in verified Buzz DMs, channels and forum threads, receive through the relay or CLI polling, and send scoped replies, files and notices through the Buzz CLI. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [IRC spec](IRC_ADAPTER_SPEC.md) · [Hermes Buzz guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/buzz.md) · [Buzz relay protocol](https://github.com/block/buzz/blob/main/NOSTR.md) · [Next adapter, BlueBubbles](BLUEBUBBLES_ADAPTER_SPEC.md)

## Registration and verified transports

Put the factory, relay client and typed CLI wrapper in `hermes-gateway::messaging::buzz`. Bind the relay/community URL, member public key and private signing ref to the owning profile. Verify membership and effective relay identity, including for multi-community paths. Use NIP-42 challenge response with ephemeral challenge state and the expected origin. Suppress own public-key echoes. Verify event IDs and NIP-01 signatures before accepting raw WebSocket event content. Trust CLI observations only from a qualified, scoped process and validate their community, channel, schema and identity. Construct fixed CLI arguments, send content through its structured input, and bound process runtime and output. Never put signing material in public arguments or diagnostics. Expose approved Buzz commands to the agent through native scoped tools, with the credential available only to the authorized invocation. [Mercury adapter seam](src/messaging/types.rs) · [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md) · [NIP-42](https://github.com/nostr-protocol/nips/blob/master/42.md)

Discover joined channels and private Buzz conversations through authenticated membership and CLI results. Use a verified DM designation, not a guessed label or message tag. Select explicit watched channels or join-authorized discovery mode. Membership updates and archive or permission changes refresh eligible subscriptions and bind no work by themselves. A removed membership fences protected content and sends. Prefer authenticated WebSocket subscription with reconnect and inactivity watchdog. Support current CLI polling over the same eligible conversations. An explicit mode switch or verified fallback must share durable identities and use a new transport lease to fence stale readers. [Hermes relay and polling paths](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/buzz/adapter.py#L1185)

## Intake and conversations

Use original Nostr event IDs per verified community and exact membership route. Normalize ordinary chat and supported forum post/comment kinds. Record receipt, actor, thread root, event time and disposition before moving recovery state. Initial discovery seeds a baseline without admitting old history. After reconnect reuse the durable timestamp and IDs at its inclusive boundary, with late-event overlap and bounds. Merge live and poll copies into the same ordered preparation per route. Do not skip same-second arrivals, advance past an uncommitted input or treat a saturated result page as proof of continuity. Report gaps where retained data or provider evidence cannot fill a bounded interval. [Hermes Buzz cursor handling](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/buzz/buzz_cursors.py)

Apply participant/public-key grants, verified room membership and optional bot handoff and loop guard. DMs need no addressing syntax. In shared chat require supported verified mentions, exact addressing or an authorized reply to the bot, unless the room explicitly enables free response. Treat display names as presentation. Separate reaction-only grants from turns, files and notifications. Use NIP-10 thread topology and verified parent/root evidence for reply destination and session binding. Keep a forum comment on its forum root. Apply explicit flat-mode policy consistently to all relevant sends. A hidden DM or detached thread cannot be silently published to a wider channel. Route text commands and privileged controls through the native authority. [Buzz thread protocol](https://github.com/block/buzz/blob/main/NOSTR.md) · [Hermes Buzz thread tests](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_buzz_thread_topology.py)

## Files and ordered effects

For inbound `imeta` attachments, require authorized source, exact configured HTTPS origin, declared byte count and SHA-256 verified against bounded bytes before staging. Deny redirects and unsolicited credentials. Support text plus file-only images, video, voice and documents and route audio through the host. Protected file reads need their own qualified CLI capability. Send native files and media where the CLI can publish them under the configured actor, purpose and channel. Keep the final media and caption ordered and bound to the original thread. Support explicitly allowed reactions and progress, with quiet final-only behavior by default. Avoid automatic broad mentions. [Hermes Buzz attachment policy](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/buzz.md#inbound-attachments)

Persist CLI send arguments, intent and preparation before dispatch. Capture the authenticated relay event identity from the supported CLI receipt and confirm it in scope where needed. A zero process exit without valid provider evidence or a process interruption after dispatch may be uncertain. Never re-sign a possibly delivered post as a new event to recover it. If the qualified transport can prepare and retransmit the exact same signed event within its replay guarantee, retain that event and apply the shared rules. Verify membership and original recipient after reopening. Use the shared outbox for explicitly verified home delivery, manual sends and background results. [Hermes Buzz send receipt](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/buzz/adapter.py#L822)

## Implementation and acceptance

| Step | Prerequisite | Evidence |
| --- | --- | --- |
| Community and transport | IRC live acceptance and shared conformance | Verified signing and membership, isolated relay scopes, WebSocket and polling fixtures. |
| Routes, media and delivery | Durable intake | DM and forum topology, authorized artifacts, CLI receipt recovery and native commands. |
| Live acceptance | Transport and shared conformance | Real Buzz community, CLI and clients prove both intake modes and authorized effects through restart. |

Use a scripted NIP-42 relay, CLI process fixture and media endpoint through the production adapter and gateway. Test wrong relay or grant, membership discovery and revocation, absent `EOSE`, inclusive watermark, repeated event and cross-transport replay, forked thread topology, denied actor, tampered media and partial CLI failure. Run shared conformance and `cargo test --locked --workspace`. In a real community verify DM discovery, an authorized mention, forum reply, media, no repeat after socket loss or process restart, and a home notification from the verified account. Switch to polling and prove equivalent durable routing. Record CLI/relay version and supported read and effect evidence. [Hermes Buzz fixtures](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_buzz_websocket.py)
