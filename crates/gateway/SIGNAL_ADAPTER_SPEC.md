# Signal stock plugin implementation spec

Register Signal as its own stock messaging plugin, platform key `signal`. Start after WhatsApp Business Cloud API passes live acceptance and the expanded shared stock-plugin contract passes conformance. A headless Mercury profile can receive and reply in an authorized Signal conversation, deliver unattended results, and recover committed work across gateway or daemon restarts. The reference is Hermes v0.23.4's bundled Signal adapter and the current signal-cli HTTP interface. [Shared gateway contract](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [Hermes Signal manifest](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/signal/plugin.yaml) · [Hermes Signal guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/signal.md)

## Architecture and account setup

Put the factory and wire client in `hermes-gateway::messaging::signal`. Use the existing Rust HTTP client for the signal-cli JSON-RPC and Server-Sent Events (SSE) endpoints. The operator links signal-cli to an existing Signal account from the primary phone and runs the daemon with protected state for that deployment. Mercury supplies private profile setup and diagnostics for the daemon and account. Signal-cli owns the linked-device keys, protocol sessions and its attachment cache. The Mercury profile owner supplies policy, conversation bindings, native execution and the outbox. Its ordinary operations can send, react, and read scoped data. Account registration and contact trust changes stay with the operator. [Hermes linked-device setup](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/signal.md#step-1-link-your-signal-account) · [signal-cli HTTP and JSON-RPC](https://github.com/AsamK/signal-cli/blob/v0.14.10/man/signal-cli-jsonrpc.5.adoc)

- Use an explicitly configured private loopback HTTP endpoint inside the daemon owner's trust boundary. Treat the reachable endpoint as credential-bearing. Keep it off public listeners, ambient HTTP proxies, and redirects. Configure the daemon with account-addressable JSON-RPC so Mercury can discover and verify the intended linked account. Use `listAccounts` to bind the stable Account Identifier (ACI) and optional number. Probe the daemon `version` RPC against the tested interface. The `/api/v1/check` response establishes HTTP liveness. Readiness additionally requires verified account selection and a working receive stream. [signal-cli account discovery](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/commands/ListAccountsCommand.java) · [signal-cli HTTP handler](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/http/HttpServerHandler.java)
- Give each verified account one active intake lease across profiles and fence the receiver and account generations on reconnect, disable, and takeover. Prefer one linked account in its own protected daemon data directory. For a trusted daemon with several accounts under one receiver owner, select and verify one exact account per stream and per account-scoped RPC. Validate each incoming account against that binding. A same-account relink keeps routes and receipts after re-verification. A different ACI requires a new binding. Surface unreachable daemon, unsupported version, account mismatch, lost registration, degraded receive continuity and send failures. Redact phone numbers and message contents from diagnostics. Document receive-on-connection mode for the SSE deployment and disable printing message payloads to the daemon's console. Use a supported signal-cli release and its declared runtime and platform packages. Validate the current transport version at implementation and live acceptance. [signal-cli JSON-RPC manual](https://github.com/AsamK/signal-cli/blob/v0.14.10/man/signal-cli-jsonrpc.5.adoc) · [signal-cli release requirements](https://github.com/AsamK/signal-cli/blob/v0.14.10/README.md#installation)

## Streaming intake and recovery

Connect to `/api/v1/events` for the verified account. Parse bounded SSE frames, including receive events, event IDs and keepalive comments. Supervise stream health and reconnect with bounded jittered backoff. Track HTTP liveness, verified receive progress, continuity of intake and send success independently. A healthy check endpoint with a stalled stream triggers a stream reconnect. Store each host disposition and its safe checkpoint before advancing the prefix. Leave model work, media staging, and slow context reads behind the durable intake boundary. Close on a failed commit and resume at the last persisted event ID. [Hermes Signal stream lifecycle](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/signal/adapter.py#L284) · [signal-cli SSE handler](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/http/HttpServerHandler.java#L179)

Resume with `Last-Event-ID` in the same verified account and endpoint scope. The tested daemon's IDs carry an instance prefix and sequence, with a ring of 1,000 events in memory. A new instance or an out-of-window cursor can return retained events without a reset marker. Keep the durable Signal message identity separate from that cursor. Verify replay continuity when the stream provides enough evidence, report an observed gap or unverified continuity otherwise, and continue from retained, current-account events through ordinary deduplication and policy. A sequence jump in a filtered multi-account feed alone gives insufficient evidence of a missing event for that account. Recover all previously committed work from Mercury storage. There is no adapter-controlled upstream acknowledgement or durable daemon history scan on this interface. [signal-cli SSE replay buffer](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/http/SseEventBuffer.java) · [Gateway intake and recovery](ADAPTER_CONTRACT.md#intake-ordering-and-execution-recovery)

For an ordinary message, derive the logical identity from the verified local account, exact DM or group, authenticated sender and Signal sent timestamp. Keep the authentic device and operation type where needed to distinguish events. A duplicate with a different SSE ID or a verified alternate sender identifier reads the original receipt. A conflicting payload under the same immutable message key surfaces a conflict. A receipt, typing event, story, group update, or contentless protocol event produces no ordinary turn. Normalize a supported `editMessage` as its own revision of the original author and chat's `targetSentTimestamp`. Update an unclaimed input through native queue edit. A correction after claim can enter as a single authorized follow-up tied to the original input. An unmatched edit produces a scoped refusal. [signal-cli message envelope](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/json/JsonMessageEnvelope.java) · [Signal edit payload](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/json/JsonEditMessage.java)

## Routes, identity and native controls

- **DMs and groups.** Accept DMs under allowlists, explicit open admission or native DM pairing. The default group policy is disabled. Authorized groups use exact group IDs, current membership and applicable participant or operator grants. Support a group allowlist, an explicit policy for groups the account belongs to, and mention-gated or free-response behavior. Recognize mentions using the authenticated message ranges and verified account identifiers. Use the configured shared or per-sender session and preserve the exact DM or group per reply. An explicitly configured peer bot uses the native handoff grants and loop guard under its verified identity. Honor group send restrictions. Recheck permissions before preparing media, claiming work or dispatching. [Hermes Signal access control](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/signal.md#access-control) · [signal-cli group commands](https://github.com/AsamK/signal-cli/blob/v0.14.10/man/signal-cli.1.adoc)
- **Signal identity.** Prefer verified service identities and accept a peer with no visible phone number. Treat ACI, phone-number identifier (PNI), and E.164 number as distinct namespaces. Use daemon-provided account or contact evidence to verify an association. Preserve the original transport address and send to the already authorized identity after any alias resolution. Detect conflicting reassignment. Untrusted identity results block work for the affected recipient until the operator verifies the change through Signal's trust workflow. Mercury's allowlist cannot renew Signal transport trust. [signal-cli recipient identifiers](https://github.com/AsamK/signal-cli/blob/v0.14.10/man/signal-cli.1.adoc#L22) · [Signal phone-number privacy](https://support.signal.org/hc/en-us/articles/6829998083994-Phone-Number-Privacy-and-Usernames-Deeper-Dive) · [Signal safety numbers](https://support.signal.org/hc/en-us/articles/360007060632-What-is-a-safety-number-and-why-do-I-see-that-it-changed)
- **Note to Self and owner messages.** For verified linked-device sync-sent frames, accept new Note to Self messages from the approved owner device. Allow owner-authored group sync-sents only when that group and actor policy also allow the input. Check the verified local account, source device, exact destination, and durable outbound keys before classifying either kind of event. A known Mercury send is an echo even if it arrives before the RPC response or after a restart. Ambiguous sender or destination evidence starts no turn and invokes no control. Never use a timestamp alone to classify an arbitrary sync-sent frame. [Hermes Note to Self guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/signal.md#note-to-self-single-number-setup) · [Hermes Signal sync-sent fixtures](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_signal.py#L1296)
- **Commands, replies and quotes.** Use the native text command catalog for supported session and model selection, skills, queue and interruption, help and status, and operator-authorized home-target setup. Bind text approvals and clarification answers to the exact actor, route, prompt and native generation. Preserve quote author, timestamp and destination together. A verified quote may reference the original input or a confirmed outbound part in that same chat. Include only authorized quote context. Keep the reply anchored to the message when permission permits and send the final content through the outbox. [Gateway control and quote requirements](ADAPTER_CONTRACT.md#shared-requirements-for-stock-plugins) · [signal-cli send and quote parameters](https://github.com/AsamK/signal-cli/blob/v0.14.10/man/signal-cli.1.adoc#L341)

## Media, presentation and delivery

**Attachments and voice.** Resolve each attachment ID from its authenticated source receipt after policy admits the read. Signal-cli stores incoming attachment bytes. Fetch them through account-scoped `getAttachment` with the original sender or group reference and decode into bounded private profile staging. Enforce size limits on the actual bytes and accept validated image, video, document and audio types, including media-only input. Keep the daemon cache under its own protected deployment policy. Use profile transcription and synthesis and deliver generated speech as a native audio attachment. Prepare outbound media from approved artifacts using bounded signal-cli attachment data. The adapter budget is up to 100 MiB per file and 32 files per message, with a bounded aggregate request size. Split large image sets into ordered and individually recoverable batches. Expose extended upload waits through the authorized delivery status. An unavailable attachment yields a scoped disposition. Treat view-once content or disappearing content with unsupported retention as a typed refusal before copying it into Mercury. [Hermes Signal attachments](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/signal.md#attachments) · [signal-cli attachment reads](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/commands/GetAttachmentCommand.java)

**Formatting and status.** Render Signal styles for bold, italic, monospace, strikethrough and spoilers. Apply the 8,000 UTF-16 unit budget, including numbered chunk suffixes, and recalculate ranges inside each Unicode-safe chunk. Quote the authorized original message on the first eligible part. Offer expiring typing for authorized active turns and opt-in reaction-based processing status. Bind a reaction to the exact chat, original author and timestamp. Track confirmed processing markers so completion or cancellation can retire them after a restart. Add a success or failure reaction only when current policy permits it. Limit revocation cleanup to removal of the gateway's own marker under a currently valid account lease and transport permission. Signal publishes committed final messages with no editable stream in this workflow. Route routine, signed webhook, background and manual sends to a verified home, direct, or group destination through the same formatting and outbox. [Hermes Signal formatting and progress](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/signal.md#native-formatting-reply-quotes-and-reactions) · [Hermes reaction hooks](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/signal/adapter.py#L963)

**Receipts and uncertain outcomes.** Reserve a unique, daemon-valid Signal sent timestamp under the verified account at the durable send claim, before invoking a timestamp-capable `send` RPC. Associate the timestamp with the leased attempt, exact destination, and intended recipient evidence. The RPC ID correlates the HTTP response. The sent timestamp forms part of the message identity and gives no guarantee of server idempotency. Store Signal's typed send results per recipient, including those carried in a JSON-RPC error. Match the RPC response ID, any returned send timestamp and reported recipients to the leased attempt. An HTTP success status alone gives no acceptance evidence. A group operation can be partially accepted. Preserve the accepted recipients and surface failed or uncertain recipients. An accepted or uncertain recipient prevents resending the whole group part. If some failures are definitive, record a terminal partial outcome when the supported group operation offers no authorized retry for that subset. A lost response or ambiguous network result fences unresolved work for the destination. [signal-cli send timestamp](https://github.com/AsamK/signal-cli/blob/v0.14.10/man/signal-cli.1.adoc#L341) · [signal-cli per-recipient outcomes](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/json/JsonSendMessageResult.java)

Keep rate-limit retry deadlines on a verified account and any narrower retry domain. Honor Signal's documented retry evidence and pace attachment batches before leasing another publish attempt. Retry only on confirmed non-acceptance. Consume delivery, read and viewed receipts as later evidence. Associate a receipt timestamp with the reserved message identity and verify its account and sender against the recorded intended recipient. A status for one member proves nothing about other members. A matching authenticated receipt may settle that member's uncertain attempt. Keep the remaining uncertainty or verified partial outcome visible. [Hermes Signal attachment pacing](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/signal/signal_rate_limit.py) · [signal-cli receipt schema](https://github.com/AsamK/signal-cli/blob/v0.14.10/src/main/java/org/asamk/signal/json/JsonReceiptMessage.java)

## Implementation and acceptance

| Work | Depends on | Ready when |
| --- | --- | --- |
| Private daemon setup and connection | Shared stock-plugin gate and WhatsApp Business Cloud API live acceptance | Verify the named current account, connect under the lease, report readiness and recover or show a continuity gap on reconnect. |
| Durable intake and routes | Verified connection and shared identity, intake and policy API | DMs, Note to Self, authorized groups, membership revocation, quotes, text controls and incoming edits pass transport fixtures across restarts. |
| Media, reactions and outbox | Authorized route and shared preparation and delivery APIs | Attachments, formatted replies and notifications recover with ordered receipts. Partial group acceptance, uncertain sends, echo suppression and later status pass the transport gate. |
| Live acceptance | All Signal transport cases | Linked accounts can complete the real Signal workflows with recorded intake, send and recovery evidence. |

Use a scripted signal-cli HTTP/SSE server through the production Rust adapter and real Mercury profile owner. Use disposable profile storage, a deterministic provider and the existing scoped audio seam. Run the Signal transport suite, the shared polling and push conformance suites, and `cargo test --locked --workspace`. [Gateway owner tests](tests/owner.rs) · [Hermes Signal fixtures](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_signal.py)

| Transport case | Evidence |
| --- | --- |
| Setup, leases and recovery | Reject a wrong daemon account, stale generation and alias from a second profile. Route two selected accounts on a trusted shared daemon. Exercise an idle stream, failed commit, replay within the buffer, replacement daemon and unverified continuity on a filtered stream. Verify that reuse of a cursor value leaves logical input identity intact. |
| Intake, permission and sync | Send exact duplicates and conflicting keys, messages from a peer with no visible number, verified alternate identifiers, an authorized group mention and a now-revoked member. Restart after admission and before native claim. Separately replay a genuine owner Note to Self message, a Mercury echo before the send response, and a late echo after restart. |
| Controls, media and presentation | Bind an edit to its original input. Verify an authorized quote and a cross-chat refusal, scoped text approval and stale response, bounded media-only and voice handling, Unicode style ranges on split text, and exact reaction cleanup across cancellation and revocation. |
| Delivery and rate limits | Reopen between attachment batches and after a send whose response was lost. Record an exact delayed receipt, mixed group outcomes, an identity change, and rate-limited non-acceptance. Verify that accepted parts are never repeated, the exact unresolved attempt fences its destination, and unrelated eligible work advances. |

For live acceptance, link controlled Signal accounts through the supported phone flow. Complete a DM and Note to Self exchange, a permitted group reply and a refused group or member, an anchored quote, a reaction, and a media or voice round trip. Deliver an unattended result to a verified home target using the same outbox. Restart Mercury with the daemon still running, then restart the daemon. Verify that committed inputs, the session binding, and the outbound receipt survive. Check the exposed continuity state and use a real Signal client to verify the destination and the absence of a duplicate reply. Record the tested daemon version and runtime. [Signal linked-device help](https://support.signal.org/hc/en-us/articles/360007320551-Linked-Devices)
